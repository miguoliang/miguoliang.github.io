### 结论

Meta 在 **2026 年 9 月 8 日**发布 **Muse**：面向普通人的**个人 AI Agent**，不只回答问题，还会替你把任务做完。它跑在云端一台专属的 **Muse Secure VM**（独立虚拟机）里，模型是 **Muse Spark**。入口不是新学一套控制台，而是 **Muse App** 和 **WhatsApp**——派活用法和给人发消息一样。

### 要点

- **这是个人 Agent，不是又一个问答框。** 官方写得很直：它会帮你盯进度、把事项从待办里拿走、把长期目标拆成行动计划。发布日期是 **2026-09-08**，出处是 Meta Newsroom 的产品稿，不是第三方传言。

- **每人一台云端 Secure VM，模型叫 Muse Spark。** Agent 和这个人的数据都住在这台专用虚拟机里，别人的 Agent 进不去。**Muse Spark** 是驱动它干活的模型。可以把它理解成：云端给你一台隔离电脑，Agent 在那台电脑里开浏览器、填表、代办，而不是把你的账号直接暴露给一个共享聊天服务。

- **在 Muse App 或 WhatsApp 里派任务，像发消息。** 不用先学提示词模板。你告诉它「去把这件事做掉」，它按消息往下推进；关了 App 它还可以继续跑，发邮件、付款这类敏感动作会先回来问你。

- **目前只在美国推；大多数用法免费，用量高了才订阅。** 官方写的是美国的 iOS、Android 和 muse.ai，AI 眼镜后续再来。价格只写了「日常大多数需求免费，想做更多有订阅计划」，**没有公布具体金额**——不要自行编套餐数字，以产品内展示为准。

### 怎么做

面向想试用、或要跟同事说清「这和写代码的 Copilot 不是一类东西」的 junior：

1. **先确认你在美国。** 稿子写明正在美国推出。其他地区现在把它当主力工具，会扑空。

2. **选一个入口：Muse App，或已经在用的 WhatsApp。** 两种入口的用法一样——发一条消息，把任务派出去。

3. **下指令时写「要完成的事」，而不是只提问。** 例如订行程、跟进一件待办。它在 Secure VM 里自己操作；真正发出邮件或付钱前，会征求同意。把「批准」当成和合并 PR 一样的人工关口。

4. **按需授权，不要一次开满。** 你决定它能连哪些应用、权限到哪一步（比如邮件是只读还是能代发）。凭证存在这台专属虚拟机里；这和自己做 Agent 时把密钥放进隔离环境是同一类思路，只是 Meta 替消费者封装好了。

5. **先把高频小事跑通，再决定要不要订阅。** 大多数日常用法按官方说法是免费的。确认它真能替你收尾，再为更高用量付费。
