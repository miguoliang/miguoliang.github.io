### 结论

[SaaStr](https://www.saastr.com/the-agent-led-growth-playbook-a-10-minute-inbound-booking-a-46-of-50-aeo-score-and-why-first-party-data-beats-every-signal-tool-the-agents-017) 这篇不是再讲一遍「销售该上几个 Agent」。写的是创始人 **Jason Lemkin** 和 **Amelia** 自己正在跑的获客栈：三人小团队、大约 **21** 个生产 Agent，主收入 Agent 叫 **10K**（十六个月前从帮 Amelia 少登几次 Salesforce / Notion 做起，现在接了 **30** 多套核心获客工具）。他们把「Agent 带增长」拆成两件活：用自己的 Agent 跑获客；以及当别人问 ChatGPT、Claude、Gemini「最好的 B2B 活动是哪场」时，被对方的 Agent 点名。入站侧，一条真实线索走完调研、定制方案和约课，大约 **10 分钟** 约上会；被点名侧，Muse 冷登录测了 **50** 条该出现 SaaStr 的问题，**46** 条点到了他们。Lemkin 的判断：**先把一方数据（你们自己已经有的参会、订阅、商机）交给 Agent，再补信号工具；外呼不要一上来抄四套厂商。**

### 要点

- **漏接不是因为少一个模型，是因为入站、外呼回复、续约、工单散在四处。** Amelia 今年最值钱的东西叫 **Prospector**：一张队列，获客里该跟的记录都落进来。三人加二十多个 Agent 时，入站有专人（和 Agent）看，客户仍会直接写信；外呼从四套工具往外发；续约和工单又各住一处。他们的做法不是先接满 30 套：第一周只接入站，大约第四周再接外呼，然后才是续约和支持。每类记录有一个目标，Agent 追到目标才停——入站是约上会，答不上就交给人；外呼是约上会或卖出票；支持是结案。队列一集中，Agent 才学得会：入站要跟几轮、外呼什么话术有回复、工单要碰几次。

- **10 分钟约上会，靠的是对方自己都不知道的事实，不是又买一家信号工具。** 入站来了，Prospector 先查自己库：来过活动吗、订了 Newsletter 吗、有没有未关商机、下过赞助方案吗。三方信号排第二：公司用 **Exa**，组织架构和决策人邮箱用 **Sumble**（入站的人常常不是买家），职位留空才用 **CoreSignal** 补 LinkedIn。然后生成一页给这家公司的方案（B2B 公司的对等物是定制价格/功能页），再写一封带自家约课链接的邮件——约课页是 10K 用来替换 Calendly 的，按公司出链接，并建议见 Amelia、David 还是两人一起。已有往来时，他们经常复制草稿回原帖，不另开一封 Agent 新邮件。演示里一条改过名字的 Base44 线索：对方 CEO 和高管其实来过 SaaStr，入站的人不知道；Exa 标出这是 Wix 收购的 vibe coding 平台、对标 Replit / Lovable，Amelia 把第一通电话改成直接问 Wix 怎么进决策；Sumble 给出约 **88** 人的获客编制。走完这四步，大约 10 分钟约上会。不是每条都这么快，但「真有事才来」的线索，把这些上下文摊在销售面前，转化更好；调研还贴在账户上，后面跟单不用重做。Jason 给 AI 外呼大约 **5** 分（满分 10），给人写的外呼大约 **2–3** 分——哪怕一年前，AI 也已经好过他们用过的几乎所有 SDR，所以外呼立刻全交给 Agent。分一直停在 5，是因为几乎没有一方数据。一家 vibe coding 公司入站时，10K 可以知道竞争对手是否赞助、那次 ROI、线索量、以及 Replit 是不是年度最会带线索的赞助商。第一封里写出这些，比任何抓来的信号都值钱。

- **外呼只统一「有人回了怎么办」；被别的 Agent 点名，要用冷登录测，不要问自己的聊天窗口。** 他们同时跑 Agentforce、Monaco、Artisan 和 10K。Prospector 不把每封外呼都拉进来——Amelia 试过，数据太多没用。各工具在自己平台发送、多数回写 Salesforce；有人回复才经 API / **MCP**（把外部系统接到模型上的协议）进队列，这时才建 Salesforce 记录，避免每天为从未回复的人建几千条。回复一到就开始计时，Agent 按原活动起草跟进；人回了再开第二只计时器，提醒该不该再催。最常见的失败是：销售第一封回得快，对方静三天就丢了。每天早上 Agent 会说：这个人三天没回；已经跟了两轮，换 LinkedIn，或换同公司另一个人。现场有人问为什么不合成一套。早期是厂商想让他们试用；后来是产品线不同——六位数赞助、大约 **1000** 美元的年会门票、播客和线上活动——对象几乎不重叠。一年前 Artisan 只跑门票，Amelia 不放心让同一套 Agent 混赞助和门票；现在两套都能跑、也没看到串台。他们的建议是：评两三个、最多四个，先做通一个细分；只有撞到缺口再加第二套。合同不要签长，半年后栈会长得不一样。被点名这一半，Amelia 让 Muse 对 saastr.com、saastr.ai 和年会站做 **AEO**（answer engine optimization：让回答引擎和别人的 Agent 推荐你）。Muse 自己列问题，退出登录，冷问 ChatGPT、Gemini 等——**50** 条里 **46** 条出现 SaaStr。答案并不一致：有的引旧年会数字，有的引 2027 站点，人数和人群对不上，他们的修补是把事实在各站写死再重发。可核对的事实（赞助续约率、公开价格）Agent 当证据；评价和设计几乎不看。同一周，他们问自己那一堆第三方 Agent 某项负载该怎么办，对方推荐全部迁到 **Resend**；来不及做厂商评选，当周就迁完。Resend 没打销售电话就赢了，其他厂商甚至不知道自己在被比较。

### 怎么做

面向正在给获客上 Agent、或已经买了 AI SDR、还容易「先接 30 套工具」的 junior：不必复制 10K 或 Replit 这个名字，按同一组顺序挡一遍。

1. **先做一张队列，第一周只接入站。** 销售用 Salesforce、市场用 HubSpot，就接这两套；表单、共享邮箱、外呼发出的地方，各接一个。续约如果还在表格里，把表格接上。入站通了，再接外呼回复，然后才是续约和工单。

2. **每条记录写死一个目标，追到关闭。** 入站 = 约上会或交给人；外呼 = 约上会或成单；支持 = 结案。人回、Agent 回都可以，但不能从队列里消失。

3. **入站四步按这个顺序，不要反过来。** 先查一方数据，再补三方信号，再出定制方案页，最后写邮件并带约课链接。已有往来就回原帖。约上会后，会前 10 分钟把账户调研交给见客户的人。

4. **外呼先做通一套。** 评两三个厂商，放在一个细分上推到头；只有出现「入站和外呼不是同一套能力」这种缺口，再加第二套。Prospector 只拉回复，不为没回的人建 CRM 记录。每天看：三天没回的、该换渠道或换联系人的。

5. **没有外呼名单时，从「客户的竞品和同类」做起。** Amelia 把历史客户名单交给 Muse（并写明不用于训练、聊完删对话），要每个客户的三四个竞争对手和域名，再交给外呼 Agent——这是他们现在最好的一条。接着才是直竞客户、流失客户和跳槽的 champion、活动邀约、以及从「谁在回复」反推下一批该打谁。

6. **每个月（最好每周）冷问大约十个别人的 Agent：我这类该用谁。** 不要问自己天天聊的窗口。输掉的答案逐条补可核对事实（续约率、公开价格、`llms.txt`）；赢下的答案护住。厂商评选来不及做时，对方的 Agent 已经在替买家拍板——SaaStr 自己就把一项负载当周迁到了 Resend。
